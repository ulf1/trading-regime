# Objective
Implement a daily machine learning model training pipeline that runs as a GCP Cloud Run Job. It trains a 3-state Markov Regime-Switching (MRS) model (Skill 899) for market tickers, leveraging vectorized PyTorch operations. The job operates statelessly by downloading `prices.db` and `forecasts.db` from a Google Cloud Storage (GCS) bucket, updating `forecasts.db` locally with new regime state probabilities and transition matrices, and uploading it back to GCS.

# Architecture & Constraints
- **Execution:** GCP Cloud Run Job triggered daily (e.g., at 02:00 CET) by Cloud Scheduler.
- **Storage:** "Stateless" execution. The script MUST download `prices.db` and `forecasts.db` from a GCS bucket at startup, perform training/updates locally, and upload the updated `forecasts.db` back to GCS upon completion.
- **Tech Stack:** Python 3.12. Strictly utilize `uv` (Skill 301) for dependency management and Docker caching. Required libraries: `torch` (Skill 323), `pandas` (Skill 327), `google-cloud-storage`, `sqlite3`.

# Implementation Requirements

## 1. Database Integration (`trainer/src/database.py`)
- Define SQLite connection helpers for the local `prices.db` and `forecasts.db`.
- **Trigger Check:** Implement queries to retrieve the latest date from `prices.db` (prices) and `forecasts.db` (`training_runs`).
- **Data Loading:** Select tickers having data on the latest date, then fetch up to 2000 historical rows per ticker.
- **Metadata Management:** Insert into `training_runs` with `status="running"` and `started_at` timestamp. Update to `completed_at` on finish.
- **Results Upsert:** Define functions to persist the extracted parameters (`mu`, `raw_sigma`, `p_ij` matrix) and regime probabilities (`proba_1d_k`) into `training_results`.
- Use the predefined `forecasts.db` schema.

## 2. Data Preparation (`trainer/src/dataset.py`)
- Transform the raw SQLite results into a Pandas DataFrame (`index=date`, columns=tickers).
- Sort chronologically from oldest to newest.
- Compute daily log returns: apply natural logarithm to values and use `.diff()`.
- Impute missing values with `0`.

## 3. Machine Learning Model (`trainer/src/model.py`)
- Strict compliance with **Skill 899 (PyTorch Hamilton)** and **Skill 323 (PyTorch)**.
- Implement the 3-state (bull, neutral, bear) vectorized Markov Regime-Switching model in PyTorch.
- Initialize model parameters using the most recent configuration available in `training_results` to accelerate convergence.
- Calculate regime probabilities and state transition matrices across the N time-series seamlessly via batched tensor operations.

## 4. Orchestration & Storage (`trainer/src/main.py`)
- Initialize a `pyproject.toml` file in `trainer` using `uv` for dependency management.
- Use `google-cloud-storage` to download `prices.db` and `forecasts.db` at runtime.
- Check the trigger condition (`last_data_dt > last_run_dt + 1 day`).
- Orchestrate data preparation and ML model execution.
- Only upload `forecasts.db` back to the GCS bucket at the end of the run (since `prices.db` is read-only for this job).

## 5. Containerization (`trainer/Dockerfile`)
- Create a multi-stage Dockerfile optimized for `uv` caching, aligned with the datasync/findticker architectural style.

## 6. Testing (`trainer/tests/`)
- Adhere to **Skill 323-unittest (PyTorch)** and **Skill 899-unittest**.
- Unit test database queries and transformations.
- Unit test PyTorch model tensor shapes, reparameterization constraints, and determinism.
- Integration test for the main orchestrator with mocked GCS clients.

## 7. Deployment
- The GCP Cloud Run Job and Cloud Scheduler should be managed via Terraform (`infra/`), leveraging standard terraform skill best practices. Memory allocation should account for PyTorch model tensor sizes.
